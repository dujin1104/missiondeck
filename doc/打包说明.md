# 打包说明（生成 Windows / macOS 安装包）

本项目用 **GitHub Actions** 自动出安装包，无需本地准备 Windows / macOS 编译环境。
代码推到 GitHub 后，打一个版本标签即可自动构建，产物直接作为 Release 附件下载。

---

## 一、最快上手（打标签触发）

在仓库根目录执行：

```bash
git tag v0.1.0
git push origin v0.1.0
```

> 标签名必须以 `v` 开头（如 `v0.1.0`、`v1.2.3`）。

推送标签后：
1. 打开仓库 **Actions** 页，看到 `Release` 工作流开始运行（两个 job：
   `build-windows` 先跑并建草稿，`build-macos` 随后把 macOS 包追加进去）。
2. 首次构建约 **15 分钟**。
3. 完成后进仓库 **Releases** → 草稿「任务工作台 v0.1.0」→ **发布**。

发布后即可下载：

| 文件 | 平台 | 说明 |
| --- | --- | --- |
| `任务工作台_x.x.x_x64-setup.exe` | Windows | NSIS 安装包 |
| `任务工作台_x.x.x_x64.dmg` | macOS | 通用安装包（Intel + Apple Silicon） |

> Windows 只打 NSIS。产品名含中文时 MSI（WiX）会因代码页 1252 报错 `LGHT0311`，故不使用。

---

## 二、不推标签也能构建（手动触发）

仓库 **Actions → Release → Run workflow**，选择 `main` 分支运行即可，效果同上。

---

## 三、构建原理（可选了解）

工作流文件：`.github/workflows/release.yml`。

- `build-windows`：在 `windows-latest` 跑 `tauri build`，产出 NSIS + MSI。
- `build-macos`：`needs: build-windows`，在 `macos-latest` 跑
  `tauri build --target universal-apple-darwin`，产出通用 `.dmg`，
  并追加到**同一个** Release 草稿。
- 两者用相同 `tagName`，自动共享同一 Release。

---

## 四、本地原生打包（不依赖 GitHub，可选）

若想在本地直接出包：

### Windows
准备：Rust（rustup）+ Node.js + VS Build Tools（勾选「使用 C++ 的桌面开发」）+ WebView2（Win11 自带）。
```bash
npm install
npm run tauri build -- --bundles nsis
# 产物：src-tauri/target/release/bundle/nsis/*.exe
# 注意：不要打 msi，中文产品名会触发 WiX 代码页错误
```

### macOS
准备：Rust + Node.js + Xcode Command Line Tools。
```bash
npm install
npm run tauri build
# 产物：src-tauri/target/release/bundle/macos/*.app 、 bundle/dmg/*.dmg
```

### macOS 交叉编译裸 exe（仅测试，无安装包）
```bash
rustup target add x86_64-pc-windows-gnu && brew install mingw-w64
cd src-tauri && cargo build --release --target x86_64-pc-windows-gnu
```

## 五、未签名提示（重要）

当前未做代码签名，首次运行会被系统拦截：

- **Windows**：SmartScreen 报警告 → 点「更多信息 → 仍要运行」。
- **macOS**：Gatekeeper 拦截 → 右键「任务工作台.app」→ 打开；
  或安装到 `Applications` 后在终端执行 `xattr -cr /Applications/任务工作台.app`。

> 如需消除警告，需在对应平台配置签名证书（Apple Developer / 代码签名证书），
> 并在工作流里注入相关密钥后重新构建。
